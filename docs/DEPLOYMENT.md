# 网页控制台与探测节点部署

部署版本：`v0.1.1`。先部署新版控制台，再升级节点；节点上线并报告 `udp` 能力后即可创建 UDP 检测。现有数据、加密密钥和节点身份需要保留。

## 控制台

从 [Dashboard Release](https://github.com/sihuangtech/probelune-dashboard/releases/tag/v0.1.1) 下载对应 Linux 架构的部署包和 `SHA256SUMS`，核验后解压。包中包含服务程序和已构建的 `web/` 网页文件。以普通用户启动：

```sh
./probelune-dashboard --listen 127.0.0.1:8080 --data ./data --web ./web
```

首次启动后，从服务器私有目录读取 `data/setup-token`，在网页初始化管理员。外网访问通过 HTTPS 反向代理转发到该地址。生产运行请使用 systemd 等服务管理器，参见 Dashboard 仓库的 [运维文档](https://github.com/sihuangtech/probelune-dashboard/blob/main/docs/OPERATIONS.md)。

已有实例先备份数据库和 `encryption.key`，替换程序与网页文件，继续使用原 `--data` 路径。不要把解压目录中的新空目录当作已有数据目录。新增索引自动建立；新增字段与现有协议 v1 兼容。

源码容器部署继续支持：

```sh
git clone https://github.com/sihuangtech/probelune-dashboard.git
cd probelune-dashboard
docker compose up -d --build
```

## 探测节点

进入网页“探测节点”，添加节点并选择 Linux x86_64 或 ARM64。复制生成的二进制安装命令；命令会下载程序并核验 SHA-256。注册令牌有效期为 10 分钟，超时后在网页重新签发。使用 Docker 时，应先构建镜像，再签发凭据，避免构建耗尽有效期。

节点只主动连接控制台。UDP、HTTP、TCP 和 DNS 不需要原始套接字权限；ICMP、MTR 按节点运行环境单独授权。内网目标需为该节点显式允许对应 CIDR。

## 周期、状态页与历史色块

1. 创建或编辑监测，配置“间隔（秒）”。支持 15—86400 秒，必须大于单次超时。例如 `60` 是每分钟检测，`900` 是每 15 分钟，`3600` 是每小时。
2. 在实例设置开启“公开状态页”，并仅为需要公开的监测勾选“公开到状态页”，然后访问 `/status`。监测详情无需公开开关也能查看自己的历史色块。
3. 色块粒度独立于探测周期。默认 15 分钟，可选每小时或自定义 5 分钟倍数；回看范围最长 720 小时，最多 2016 个色块。设置会在当前浏览器保存。
4. 点击色块查看统计或定位历史明细。绿色表示已观察到正常样本，橙红色表示存在检查失败；斜纹表示覆盖不足，灰色表示无有效样本。新实例不会凭空生成过去的正常记录。
5. 可用率为成功样本占有效目标检查的比例，不是时间型 SLA；覆盖率衡量应执行周期的实际有效观测。节点离线和执行错误不当作目标正常。

UDP 需要指定端口、UTF-8 或 HEX 请求内容；可填写期望响应包含内容。必须收到非空响应才算成功。超时表示未观察到响应，不能证明端口已关闭。
